# ETF 溢价双向穿越提醒设计

日期：2026-10-01

## 目标

优化现有 ETF 溢价提醒：每只 ETF 支持独立配置“涨破高位”和“跌破低位”两个方向，并且只在溢价率穿越阈值时推送一次。现有单阈值数据继续可读，默认视为“涨破”配置。

本次范围：

- 支持 `513100` 纳指ETF国泰和 `513500` 标普500ETF博时。
- 每个方向独立启用、设置阈值和维护去重状态。
- 低阈值允许负溢价率。
- 复用现有用户推送渠道、全局推送开关、免打扰和行情新鲜度校验。

不在范围：新增 ETF 标的、推送渠道、历史提醒列表、用户级自定义冷却时间。

## 方案

采用现有 `etf_premium_alerts` 表扩展字段，而不是拆分方向明细表或存储 JSON。这样能保留现有 API 路径、设置页结构和已有单阈值数据，迁移范围最小。

### 数据模型

保留现有字段作为涨破方向：

- `enabled`：涨破提醒是否启用。
- `threshold_pct`：涨破阈值。
- `above_threshold`：当前是否在高阈值上方。
- 现有 `last_triggered_*` 字段继续记录该 ETF 最近一次触发，增加方向字段以便展示。

新增跌破方向字段：

- `below_enabled INTEGER NOT NULL DEFAULT 0`
- `below_threshold_pct REAL NOT NULL DEFAULT 0`
- `below_threshold INTEGER NOT NULL DEFAULT 0`
- `below_initialized INTEGER NOT NULL DEFAULT 0`

为涨破方向增加首次观察标记：

- `above_initialized INTEGER NOT NULL DEFAULT 0`

为最近触发记录增加方向：

- `last_direction TEXT NOT NULL DEFAULT ''`

阈值范围为：涨破 `0%` 到 `100%`，跌破 `-100%` 到 `100%`。当两个方向同时启用时，要求低阈值小于高阈值；只启用一个方向时，另一方向的阈值仍须是合法数值，但不参与触发。

数据库初始化沿用现有 `ensure_*_columns` 模式，按列存在性补充字段。既有记录的 `enabled` 和 `threshold_pct` 直接作为涨破配置，跌破默认为关闭，不改变已有用户的有效设置。

### API

保留接口：

- `GET /api/me/etf-premium-alerts`
- `PUT /api/me/etf-premium-alerts/{symbol}`

GET 返回：

```json
{
  "items": [
    {
      "symbol": "513100",
      "name": "纳指ETF国泰",
      "above": {"enabled": true, "threshold_pct": 8.0},
      "below": {"enabled": true, "threshold_pct": 2.0}
    }
  ],
  "notify_enabled": true
}
```

PUT 接收：

```json
{
  "above": {"enabled": true, "threshold_pct": 8.0},
  "below": {"enabled": true, "threshold_pct": 2.0}
}
```

服务端校验 ETF 代码、有限数值、涨破 `0..100`、跌破 `-100..100` 的范围及启用时的上下阈值关系。配置发生变化时清空对应方向的越界和初始化状态；返回保存后的完整 ETF 设置。

### 触发流程

行情轮询仍按现有 30 秒周期执行，并先通过交易时段、价格、IOPV 和报价时间新鲜度检查。`alertable` 不再固定返回 `false`，而是在这些数据有效且新鲜时允许评估；页面继续显示 IOPV 实时性说明。

每个有效报价分别检查两个方向：

- 涨破：第一次有效观察只写入基线；之后从 `rate <= high` 变成 `rate > high` 时 claim，推送后标记当前位于高位。只要持续高于阈值，不重复推送；回到 `rate <= high` 后重新武装。
- 跌破：第一次有效观察只写入基线；之后从 `rate >= low` 变成 `rate < low` 时 claim，推送后标记当前位于低位。只要持续低于阈值，不重复推送；回到 `rate >= low` 后重新武装。

claim 使用 SQLite 条件更新，确保同一用户、ETF、方向在并发轮询下最多被一个任务领取。推送失败仍记录 `failed`，不改变方向越界状态，避免短时间内因投递故障重复触发。

推送标题和正文标明方向、当前溢价率、对应阈值、行情时间和 IOPV 信息：

- `ETF 溢价上涨穿越提醒`
- `ETF 溢价下跌穿越提醒`

## 界面

设置页保留每只 ETF 一行，但行内分为两个方向区块：

- `涨破`：独立开关、百分比输入（`0..100`）。
- `跌破`：独立开关、百分比输入（`-100..100`）。
- 一个保存按钮同时提交该 ETF 的两组设置。

输入使用 `type=number`、步进 `0.01`，涨破范围 `0..100`、跌破范围 `-100..100`。保存中禁用当前 ETF 行；失败时保留草稿并显示现有错误提示模式。说明文字改为双向穿越语义，并说明首次有效行情只建立基线、持续越界不会重复推送。

市场页最近触发区域增加方向和对应阈值，移除“当前不发送提醒”的错误说明；行情延迟时仍只保留最近数据，不评估提醒。

## 错误处理与兼容

- 未登录、未知 ETF、非有限值和范围外阈值返回 `400` 或现有认证错误。
- 上下阈值关系无效时拒绝整组保存，避免只保存半套配置。
- 关闭某一方向只停止该方向，另一方向继续工作。
- 全局推送关闭、免打扰或无可用渠道时沿用现有 `send_user_alert` 结果和投递状态。
- 旧数据库记录不丢失；旧单阈值被当作涨破配置，升级后不会因为已有溢价率越界而立即补发。

## 测试与验收

Rust 单测覆盖：

- 首次观察只建立基线。
- 涨破、跌破的单次触发、持续越界去重和回到另一侧后的再次触发。
- 负阈值和上下阈值关系校验。
- 保存配置重置对应方向状态，关闭方向不触发。
- 失效或过期行情、全局推送关闭不产生实际投递。
- API 的旧数据兼容、完整格式保存、非法输入和用户隔离。

前端验证覆盖：

- 设置页加载、编辑两方向、保存后刷新保持。
- 保存失败草稿保留和窄屏布局。
- 市场页最近触发显示涨破/跌破方向。
- 静态 JS 语法检查、资源指纹校验和本地市场页浏览器检查。
